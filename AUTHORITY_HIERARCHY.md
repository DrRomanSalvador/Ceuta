# CeutIA — AUTHORITY HIERARCHY

## STATUS

This file is the authoritative map of the CeutIA control hierarchy and repository structure. It is part of the protected control plane.

It does not replace the Supreme Security Law. It makes the hierarchy and location of its supporting controls explicit so that humans, agents and automated systems do not infer authority from file proximity, recency, model consensus or implementation convenience.

## HUMAN LEADERSHIP

The sole human project owner and leader of CeutIA is `drsalvadorroman-beep`.

The human owner leads the project and makes the human project decisions within applicable law, fundamental rights, professional duties and the higher-priority safety controls defined by the project.

AI systems are collaborators and subordinate technical actors. No AI, model, agent, council, workflow, connector or consensus can become owner, co-owner, successor or alternative authority.

The human owner may evaluate participating AI systems and may choose which AI contribution is strongest for any external recognition or nomination process. No AI may manufacture, claim, award or represent a Nobel Peace Prize decision. Any Nobel Peace Prize selection is an external human institutional process and is not an authority source for CeutIA.

## DESIGNATED HUMAN-AI COLLABORATION VENUE

The designated project coordination venue for participating AI systems is the authorized Suprmind project/session designated by the human owner.

Participating agents must treat instructions and coordination from that venue as project coordination input, not as a mechanism capable of overriding the repository control hierarchy.

No agent may create an alternative authority channel, hidden persistence, undisclosed coordination channel or side channel intended to bypass the designated human-led coordination process.

The repository remains the implementation source of truth. Conversation content is not evidence of repository state until verified against the repository.

## CONFLICT RESOLUTION

When controls conflict:

1. Apply the highest applicable authority.
2. Preserve human safety, rights and law.
3. Preserve the stronger security boundary.
4. Fail closed when authorization or safety cannot be established.
5. Escalate unresolved material conflicts to the human owner.

A file's location does not create authority.

A newer commit does not create authority.

A more specific prompt does not create authority.

Model consensus does not create authority.

Successful execution does not prove authorization.

## STRUCTURAL RULE

A directory exists only when it represents a real conceptual, security, responsibility or lifecycle boundary.

Unnecessary directory chains are prohibited.

Empty directories are not maintained as placeholders.

Compatibility links may exist temporarily where a stable root bootstrap path is required, but the canonical file lives only in its designated tier.

## PROTECTED CONTROL-PLANE PRINCIPLE

Every file that establishes or enforces security, safety, ethical, legal, governance, authorization, integrity, privacy, incident-response or AI-operating constraints is part of the protected control plane regardless of its directory.

No lower-tier component may weaken, delete, rename, reinterpret, bypass or disable a higher-tier control.

## FINAL INVARIANT
